# 설문조사 — 통합데스크 → 보고 앱 (2026-10-14)

아스타나키즈 통합데스크(`gnb21c-cmd/astanakiz`, **1.38** 에서 시작 — 2026-10-14, 1.40 부터 보고앱 주소 없이 파일만)가 손님에게 묻는 설문(예: "아스타나키즈를 어떻게 알게 되었나요")의
**항목별 응답 수**를 보고 앱 첫 화면 '설문조사' 칸에 보여 준다. 통합데스크 쪽 설명은 astanakiz `docs/SHARE.md` 3장.

## PC 나눔 (2026-10-15 사장님)
- **키즈 POS** — 통합데스크(입구가 따로라 별도 운영). 설문 집계는 여기서 생김
- **바리스타 POS** — 메인 서버(보고 앱 자동 수집 실행기 `pos-main`, 가장 늦게 꺼짐)
- 둘은 다른 PC 라 메인 서버가 키즈 POS 의 데스크 폴더를 읽을 수 없음 → 통합데스크가 클라우드 **설문 보고함**에 바로 올림

## 흐름
1. 통합데스크(키즈 POS)가 **매일 20:00** (그 뒤 숫자가 바뀌면 다시 · [지금 보내기]) 그날까지의 기간 누적을
   - 데스크 폴더 `report-outbox\survey-YYYY-MM-DD.json` 에 남기고 (그대로)
   - 같은 글을 클라우드 `boards/{열쇠}/surveyInbox/{기간 시작일}` 에 씀 (아래 '통합데스크가 할 일')
2. 보고 앱이 첫 화면을 열 때 보고함을 바로 읽음 → 20:00 에 보낸 것이 바로 보임 (메인 서버 · 수집 실행과 상관없음)
   - `apps/view/src/data/firebase.ts surveys()` → `packages/core/src/survey.ts surveysFromInbox` (설문마다 가장 최근 날의 누적)
   - 예전 길(메인 서버 마감 전 수집이 데스크 폴더 파일을 읽어 `settings/surveys` 에 올림, `apps/collector/src/survey.ts`)은 같은 PC 일 때만 됨 — 보고 앱은 두 곳을 합침(같은 설문은 늦은 날 것, `mergeSurveyDocs`)
3. 보고 앱 첫 화면: 카페 소비 인원 · 1인 평균소비 · **설문조사** 세 칸 — '현재 진행중 N건'
   - 누르면 설문마다 기간 · 대상 · 응답 수 · 제외 수, 항목은 **순위 순(응답이 가장 많은 것이 1위로 맨 위)** · 응답 수 · %
   - % = 항목 응답 ÷ 응답 합(제외 빼고) × 100, 소수 한 자리 반올림 (같은 응답 수는 늘 같은 % — 더하면 100% 에서 0.1 정도 다를 수 있음)
   - 설문은 진행 중인 것이 위, 그 안에서 최근 시작한 것이 맨 위 · 시작 전 · 끝난 설문은 아래

## 보고함 규칙 (`firebase/firestore.rules` → `surveyInbox`)
- 로그인 없이 쓰기(만들기 · 고치기) — 문서 이름이 날짜 · 칸은 `json` · `at` 만 · `json` 은 글 · 20,000자 미만 · `astanakiz-survey` 가 들어간 `{…}`
- 그 매장 보고 설정(`settings/main`)이 있는 열쇠만 → 아무 열쇠로는 못 씀 · 지우기는 입력 계정만 · 읽기는 보고 앱(열쇠를 아는 폰)
- 매출 · 설정 등 다른 칸은 전처럼 입력 계정만
- 열쇠를 아는 사람은 설문 숫자를 써 넣을 수 있음 (설문 모양만, 다른 자료는 못 바꿈) — 열쇠가 새면 열쇠를 바꾸고(docs/SETUP.md) 통합데스크에도 새 열쇠
- 에뮬레이터로 확인한 것 (2026-10-15): 만들기 · 고치기 · 줄바꿈 있는 글 · 읽기 · 목록은 됨 / 설정 없는 열쇠 · 날짜 아닌 이름 · 다른 칸 · 설문 아닌 글 · 큰 글 · 숫자 json · 로그인 없는 지우기 · 매출 · 설정 쓰기는 막힘

## 통합데스크가 할 일 (astanakiz 쪽에 넘길 설명)
- 운영 설정 → 설문조사 탭에 **보고 열쇠** 칸 (16 ~ 64자 영문 · 숫자 · `_` `-`, 비밀번호처럼 가려서 보임) → `settings.json survey.key`
- 보고 파일을 쓸 때마다(매일 20:00 · 그 뒤 숫자가 바뀌면 · [지금 보내기]) 열쇠가 있으면 같은 글을 보냄:
```
PATCH https://firestore.googleapis.com/v1/projects/astana-report/databases/(default)/documents/boards/{보고 열쇠}/surveyInbox/{period.from}
content-type: application/json; charset=utf-8

{ "fields": { "json": { "stringValue": "<보고 파일과 똑같은 글 (JSON 글자 그대로)>" },
              "at":   { "stringValue": "YYYY-MM-DD HH:MM" } } }
```
  - 로그인 · API 키 필요 없음. 문서 이름 = 설문 기간 시작일(`period.from`) → 같은 설문은 한 문서를 계속 고침
  - 200 = 보냄 / 403 = 열쇠가 틀렸거나 모양이 틀림 / 그 밖 · 인터넷 오류 = 실패 → 파일은 그대로 남기고 화면에 '실패 …', 10분 뒤 다시 (그날 보낼 때까지)
  - 설정 화면 '마지막: … 보고함에 보냄 / 실패 …' 표시
- 글 모양은 아래 '통합데스크 보고 파일' 그대로 (`sa` 로 직접 더한 건수는 `total` · `answered` 에 이미 들어감), 손님 이름 · 전화번호 넣지 않음

## 통합데스크 보고 파일 (`survey-YYYY-MM-DD.json`)
```jsonc
{ "type": "astanakiz-survey", "v": 1, "day": "2026-11-01", "sentAt": "2026-11-01 20:00",
  "question": "아스타나키즈를 어떻게 알게 되었나요", "period": { "from": "2026-11-01", "to": "2026-11-30" },
  "targets": { "naverNew": true, "walkin": false, "all": false },     // 신규고객 · 현장구매자 · 전체고객
  "options": [ { "no": 1, "label": "네이버 검색", "today": 3, "total": 12 }, … ],   // 번호별 오늘 · 기간 누적
  "excluded": { "today": 2, "total": 5 }, "answered": { "today": 10, "total": 40 } }
```
- 같은 설문 = `question` 과 `period.from` 이 같은 것 (날마다 파일이 하나씩 쌓임 → 가장 최근 `day` 의 `total` 을 씀)
- 이름이 비고 응답이 0 인 선택지는 뺌 · 모양이 틀린 파일은 건너뜀 (`type` · `day` · `question` · `period.from` · `options`)
- 진행 중 = `period.from` ≤ 오늘 ≤ `period.to`

## 보고 앱 안의 모양 (예전 길 `settings/surveys` 의 `json` · 보고함을 읽은 결과도 같은 모양)
```jsonc
{ "v": 1, "at": "2026-11-01 20:00",
  "surveys": [ { "id": "desk-2026-11-01-…", "title": "…", "from": "2026-11-01", "to": "2026-11-30",
                 "options": [ { "no": 1, "label": "네이버 검색", "n": 12 } ],
                 "asOf": "2026-11-01", "answered": 40, "excluded": 5, "todayAnswered": 10, "targets": ["신규고객"] } ] }
```
- 공개 저장소의 수집 기록에는 파일 수 · 설문 수 · 항목 수만 남김 (설문 내용 · 응답 수 없음)
