# 설문조사 — 통합데스크 → 보고 앱 (2026-10-14)

아스타나키즈 통합데스크(`gnb21c-cmd/astanakiz`)가 손님에게 묻는 설문(예: "아스타나키즈를 어떻게 알게 되셨나요?")의
**항목별 응답 수**를 보고 앱 첫 화면 '설문조사' 칸에 보여 준다.

## 흐름
1. 통합데스크가 **매일 20시**(또는 설문이 바뀔 때마다) POS PC 데스크 폴더에 집계 파일을 쓴다
   - 위치: `%APPDATA%\아스타나키즈 입장 데스크\survey-state.json` (desk-state 와 같은 폴더)
   - **손님 이름 · 전화번호 · 예약번호는 넣지 않는다** — 항목별 응답 수만
2. 보고 시스템 마감 전 수집(`.github/workflows/live-collect.yml`, POS 메인 PC, 30분마다 10:15 ~ 22:45)의 마지막 단계가
   그 파일을 읽어 클라우드 `boards/{열쇠}/settings/surveys` 에 올린다 (`apps/collector/src/survey.ts`, 바뀌었을 때만)
   → 20시에 쓴 파일은 보통 20시 15분 ~ 45분 실행에서 올라감
3. 보고 앱 첫 화면: 카페 소비 인원 · 1인 평균소비 · **설문조사** 세 칸 — '현재 진행중 N건', 누르면 설문마다 항목(번호 · 내용) · 응답 수 · %(합 100%)
   - 진행 중인 설문이 위, 그 안에서 **최근 시작한 것이 맨 위** · 시작 전 · 끝난 설문은 아래

## 파일 모양 (`survey-state.json`, UTF-8)
```jsonc
{
  "v": 1,
  "at": "2026-10-15T20:00:00+09:00",          // 집계한 시각
  "surveys": [                                 // 설문 여러 개 가능 (순서는 상관없음 — 보고 앱이 정렬)
    {
      "id": "how-know",                        // 설문 이름표 (영문 · 숫자, 바뀌지 않음, 설문마다 다르게)
      "title": "아스타나키즈를 어떻게 알게 되셨나요?",
      "from": "2026-10-15",                    // 시작일
      "to": null,                              // 끝일 (진행 중이면 null, 끝나면 마지막 날)
      "options": [                             // 화면 번호 순서대로
        { "no": 1, "label": "네이버 검색 · 지도", "n": 46 },   // n = 그 항목을 고른 응답 수 (누계)
        { "no": 2, "label": "인스타그램", "n": 21 },
        { "no": 3, "label": "지인 소개", "n": 17 },
        { "no": 4, "label": "기타", "n": 3 }
      ]
    }
  ]
}
```
- 진행 중 = `from` ≤ 오늘 ≤ `to`(없으면 계속). 끝난 설문도 파일에 남겨 두면 보고 앱에 '끝남'으로 아래에 보임
- %는 보고 앱이 계산 (응답 합 = 100%, 소수 한 자리, 합이 꼭 100.0 이 되게 — `packages/core/src/survey.ts surveyShares`)
- 모양이 틀린 설문 · 항목은 보고 앱에서 빠짐 (`cleanSurveys`): `id` · `title` · `from`(YYYY-MM-DD) 이 없거나, 같은 `id` 두 번, 항목 `label` 이 비었거나 같은 `no` 두 번
- 공개 저장소의 수집 기록에는 설문 수 · 항목 수만 남김 (설문 내용 · 응답 수 없음)
