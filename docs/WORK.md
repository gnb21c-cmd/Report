# 근무자 화면 — 숫자만 보는 간단한 화면 (2026-10-22 사장님)

관리자가 보는 보고 앱(B) 말고, **근무자가 폰으로 간단히 보는 화면** 하나. 보고 앱 자료에서 **수량만** 발췌해 다시 그림.

- 주소: `https://<호스팅>/w/<키 번호>/` — 키 번호는 **현장 태블릿과 같은 키**(매니저 앱 [태블릿 주소]에서 정하고 바꿈 · 바꾸면 예전 주소는 바로 막힘). 매니저 앱 [태블릿 주소] 화면에 '근무자 화면 주소' · **QR** · [주소 카톡으로 보내기] · [QR 그림 보내기 · 저장](제목 · QR · 안내가 든 그림 한 장 — 뽑아서 붙여도 됨, `apps/bakery/src/image.ts qrImage`)
- QR 은 키 번호가 든 주소라 매니저 앱에서만 만듦 (키를 바꾸면 QR 도 새로 — 예전 QR 은 막힘)
- 로그인 없음 · **매출 금액 · 손님 이름 · 전화 없음** — 근무자 화면은 숫자만 복사해 둔 문서만 읽음 (매장 열쇠 · 보고 앱 자료는 못 읽음)
- 1분마다 새로 읽음 · 체험판 `apps/bakery/dist-demo/index.html#w`

## 화면
1. **맨 위 — 재방문 이벤트 · 돈까스 예정**
   - **오늘 남은 예약**: 지금 기준, 오늘 예약 중 아직 안 온(이용완료 전) **재방문 이벤트 대상** 예약 수 → 돈까스 줄 준비
   - **내일 · 모레 · 글피**: 오늘을 뺀 3일 동안 재방문 이벤트 대상이 되는 예약 수
   - 손님 장부는 키즈 POS 통합데스크에만 있어 **통합데스크가 보내야 보임** (아래 '통합데스크가 할 일'). 오기 전에는 "통합데스크 숫자를 기다리는 중이에요"
2. **바리스타 · 베이커리 · 키친 버튼** (버튼에 오늘 지금까지 수량)
3. 버튼을 누르면 그 섹터 화면
   - 위에 두 칸: **평일 평균 수요량** · **휴일 평균 수요량** — 오늘 빼고 지난 4주(28일), 하루 섹터 목록 수량의 합의 평균 (평일 = 월 ~ 금, 휴일 = 토 · 일 · 공휴일 — 보고 설정의 휴일 더하기/빼기 반영)
   - 그 밑에 목록: **상품명 · 오늘 · 1주 · 그 달** — 오늘 = 지금까지(마감 전 숫자) · 1주 = 오늘 포함 7일 · 그 달 = 1일 ~ 오늘
   - 바리스타는 잔(샷 추가 · 시럽 · 연하게 같은 옵션 · 원두 · 드립백은 뺌), 베이커리 · 키친은 개 · 0원 줄 · 빵이 아닌 잼 · 소스는 뺌
   - 베이커리는 제빵 품목 표 순서(`BREAD_ORDER`), 바리스타 · 키친은 그 달 많이 팔린 순

## 숫자가 오는 길
- 규칙 · 검사: `packages/core/src/work.ts` (`workSummary` · `workEventOf` · `checkWorkDoc` · `checkWorkEvent`)
- **섹터 숫자** → `floor/{키}/work/now` — 바리스타 POS 하루 수집(`apps/collector/src/liveLoop.ts`)이 15분 칸마다 마감 전 수집 뒤에 `apps/collector/src/work.ts` 를 실행 (이번 달 1일(또는 28일 전) ~ 오늘 보고 + 오늘 마감 전 카페 숫자)
- **이벤트 예정 수** → `floor/{키}/work/event` — 하루 수집이 칸 사이 1분마다 통합데스크 키즈 실시간 현황(`boards/{열쇠}/deskLive/now`)의 `revisitDue` 를 숫자만 옮김 (바뀌었을 때 · 10분마다는 다시)
- 하루 수집이 도는 09:30 ~ 22:50 에만 새로 바뀜
- 보안 규칙(`firebase/firestore.rules` → `floor/{fk}/work/{doc}`): 읽기 = 키가 살아 있을 때만 · 쓰기 = 그 매장 입력 계정만, 문서 `now` · `event` · 칸 `date` · `at` · `json` 만 — **Firebase 콘솔 규칙 탭에 붙여 넣기 필요** (Deploy 는 화면만)

## 통합데스크가 할 일 (gnb21c-cmd/astanakiz — 키즈 POS)
지금 1분마다 보내는 키즈 실시간 현황 글(`astanakiz-live`, `deskLive/now`)에 칸 하나를 더함:

```jsonc
"revisitDue": {
  "today": 4,                                   // 지금 기준 오늘 예약 중 아직 이용완료 안 한(확정 · 미입장) 재방문 이벤트 대상 예약 수
  "ahead": [                                    // 오늘을 뺀 3일 (내일 · 모레 · 글피) — 날짜마다 그날 재방문 이벤트 대상 예약 수
    { "date": "2026-10-23", "n": 6 },
    { "date": "2026-10-24", "n": 9 },
    { "date": "2026-10-25", "n": 3 }
  ]
}
```
- **재방문 이벤트 대상** = 재방문 이벤트 장부(전화번호)에 있고, 그 예약 날짜가 손님의 기한(`due`, 방문일 + 기한 일수, 종료일을 넘지 않음) 안이라 오면 '2번 성공'(사은품 = 돈까스)이 되는 예약. 같은 손님이 같은 날 나눠 한 예약은 1건
- 이벤트 기간이 아니면 `"revisitDue": null` 또는 칸 없음 → 근무자 화면은 "기다리는 중"
- 내일 ~ 글피 예약은 통합데스크가 그 날짜 네이버 예약(확정)을 읽어야 셀 수 있음 — 30분 ~ 1시간마다면 충분
- 숫자만 (이름 · 전화 넣지 않음) · 근무자 화면은 0 이상 정수 · 오늘 뒤 3일 안 날짜만 받음 (`packages/core/src/deskLive.ts` `revisitDueOf`)
