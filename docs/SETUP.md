# 처음 설정 · 설치 · 매일 하는 일

따로 운영하는 서버는 없습니다. **사무실 PC 한 대(C)** 를 24시간 켜 두고 서버 역할을 맡깁니다.
C 는 사무실 공유기 안에 있어 밖(폰 LTE)에서 바로 들어올 수 없으므로, 폰(B)에는 **Google Firebase(무료 사용량 안)** 를 우편함으로 써서 전합니다.
사무실 공유기 포트를 열지 않아도 되고, 켜 두거나 관리할 컴퓨터는 C 하나뿐입니다.

```
[카페 POS] [키즈 POS] ─▶ OK포스 본사 ─▶ 웹 백오피스 nice.okpos.co.kr (총괄 아이디, 매장별 '영수증별 매출 상세현황' 엑셀)
                                                │ 직원이 받아서
   직원 PC 의 A (전체 화면 입력: 네이버 표 · 엑셀 2개) ─ 계산 ─▶ 사무실 PC C (받기 · 합치기 · 날씨) ─▶ Firebase ─▶ 폰 B
                                                                     └ 사무실 안: http://C이름:8770/b/
```

## ⓪ 먼저 시험 (Firebase 없이, 사무실에서 30분)

1. GitHub → **Actions** → **Build office** → 맨 위 초록 체크 실행 → **Artifacts** 의 `pos-report-office` 내려받기 → 압축 모두 풀기
2. 24시간 켜 둘 사무실 PC 에서 `install-c.bat` 더블클릭 → [예] → 이메일은 **Enter** (= 시험 모드), 사무실 비밀번호는 정하거나 Enter
   - 끝에 나오는 **이 PC 이름 · 주소** 를 적어 둡니다. 예전 '매출 보내기'가 깔려 있으면 저절로 지웁니다.
3. 직원 PC 에서 `install-a.bat` 더블클릭 → C 를 저절로 찾아 바탕화면 **매출 보고 입력** 아이콘을 만듭니다
4. 아이콘 → 이름(· 비밀번호) 한 번 → 어제 날짜로 열림 → 네이버 표 · 엑셀 2개 → **입력완료 · 보고자료 업로드**
5. 사무실 안 PC 나 폰(사무실 와이파이)에서 `http://C주소:8770/b/` 를 열면 보고가 보입니다

## ① Firebase 프로젝트 만들기 (사장님, 15분 · 처음 한 번)

1. https://console.firebase.google.com → 회사 구글 계정으로 로그인 → **프로젝트 추가** → 이름 예: `pos-report` (Google 애널리틱스는 꺼도 됨)
2. **Authentication** → 시작하기 → 로그인 방법 → **이메일/비밀번호** 사용 설정
3. Authentication → 사용자 → **사용자 추가** 로 C 올리기 계정 1개 (예: `office@회사도메인`, 실제 메일함 없어도 됨). 보는 사람은 계정이 필요 없음
4. **Firestore Database** → 데이터베이스 만들기 → 위치 **asia-northeast3 (서울)** → 프로덕션 모드
5. Firestore → **규칙** 탭 → 저장소의 `firebase/firestore.rules` 내용을 통째로 붙여 넣고 **게시**
6. **매장 열쇠** 정하기 — 32자 정도의 무작위 글자. 아무 PC 의 PowerShell 에서 `[guid]::NewGuid().ToString('N')`
   - 이 열쇠가 곧 보고 앱 설치 주소의 일부입니다. 열쇠를 아는 사람만 자료를 볼 수 있습니다.
7. Firestore → 데이터 → 컬렉션 `senders` 에 문서 1개 (문서 ID = 3번 이메일 **소문자**) → 칸 `board` = 6번 열쇠
8. 프로젝트 설정(⚙) → 일반 → **웹 앱 추가**(</>) → 나오는 `apiKey` 와 `projectId`, 그리고 6번 열쇠를 알려 주세요.
   - `apiKey` · `projectId` 는 비밀번호가 아닙니다. **열쇠는 회사 안에서만** 주고받아 주세요.

## ② 폰 앱(B) 올리기 (개발 측)

```bash
cd apps/view
VITE_FIREBASE_API_KEY=… VITE_FIREBASE_PROJECT_ID=… pnpm build
cd ../../firebase && npx firebase-tools deploy --only hosting,firestore:rules --project <projectId>
```

- **설치 주소: `https://<projectId>.web.app/b/<열쇠>/`** — 대표이사 · 관리자 4명에게 이 주소를 카톡 등으로 보냅니다.
- 폰에서 주소를 열고 **홈 화면에 추가**(아이폰 Safari 공유 버튼 / 안드로이드 Chrome ⋮ → 앱 설치). 로그인은 없습니다.
- 주소가 샜으면 새 열쇠를 정해 `senders` 문서의 `board` 와 C 설정을 바꾸고(`PosReport.exe setup --board …` 뒤 `PosReport.exe republish`) 새 주소를 다시 보냅니다.
- GitHub 저장소 변수 `FIREBASE_API_KEY` · `FIREBASE_PROJECT_ID` 와 비밀 값 `REPORT_BOARD_KEY`(열쇠) · `KMA_SERVICE_KEY`(기상청)를 넣어 두면 C 설치 묶음에 들어가 설치 때 묻지 않습니다.

## ③ C 를 클라우드에 연결 (시험 모드 → 실제)

1. C 에서 `C:\ProgramData\PosReport\config.json` 을 지우지 말고, 관리자 PowerShell 에서
   `& "C:\Program Files\PosReport\PosReport.exe" setup --apikey … --projectid … --board … --email … --password …`
   (또는 config.json 을 지우고 `install-c.bat` 다시 → 이메일 · 비밀번호 입력)
2. `PosReport.exe republish` — 시험 모드 동안 C 에 쌓인 보고 · 날씨를 모두 올림
3. `PosReport.exe check` 에 `[정상] 클라우드 보관함 로그인` 이 보이면 끝. 작업 스케줄러의 `PosReport-C` 를 한 번 다시 시작(또는 재부팅)

## ④ 기상청 날씨 (아스타나와 같은 키)

- 아스타나 때 공공데이터포털에서 받은 **기상청 인증키(Decoding)** 를 그대로 씁니다. 필요한 서비스: 단기예보 조회서비스 · 지상(종관, ASOS) 일자료 조회서비스
- **C 가 1시간마다** 받아 쌓고 폰에도 올립니다 (A 화면 위에도 그날 날씨가 보임).
  - 지난 날: 관측 확정값 (관측소 119 수원). 처음 한 번은 2025-01-01 부터 모두 채움
  - 오늘: 단기예보 (매장 격자 61·119, 오늘 02시 발표의 최고 · 최저). 다음 날 관측값이 오면 관측으로 바뀜
- 키는 GitHub 비밀 값 `KMA_SERVICE_KEY` 로 넣어 두면 설치 묶음에 들어갑니다 (또는 `PosReport.exe setup --kma-key …`). 키는 저장소에 넣지 않습니다.

## ⑤ 작년 비교선 채우기 (한 번)

- A 화면 아래 **지난 자료 한꺼번에 넣기** → 매장을 고르고 백오피스 **상품별 (일자별)** 엑셀(기간 길게, 조회줄수 5000)을 올림 → C 로 보내기. 매장마다 한 번씩
- 하루 합계만 들어갑니다 (시간대 그래프는 영수증별로 올린 날부터). 이미 영수증별로 올린 날은 바꾸지 않습니다.
- 카페 상품별 엑셀에는 OK포스 대분류가 있어 **상품 분류표**(바리스타 · 베이커리 · 키친 · 기타)도 함께 채워집니다 → 그 뒤로는 A 가 새 상품만 묻습니다.
- 7 · 8 · 9월 파일은 예전에 조회줄수 제한으로 잘렸습니다. 잘린 파일은 A 가 받지 않으니 한 달씩 다시 받아 주세요.

## 매일 하는 일 (사무실 — 각자 맡은 칸만 넣어도 됨, C 가 날짜별로 합침)

1. 바탕화면 **매출 보고 입력** → "yy년 mm월 dd일 기준 -1일 전의 일자 (영업마감 현재) 기준 영업 데이터를 입력하세요" — 어제 날짜로 열림
2. ① **네이버 예약 표**: 10:00 ~ 19:30, 30분마다 판매입장권 수 · 신규방문자 수 (마감 현재 방문 완료 횟수 1인 손님)
3. ② 백오피스 **영수증별 매출 상세현황** → 매장 **[카페아스타나]** 하루 → 엑셀 → 왼쪽 칸 / 매장 **[아스타나키즈]** 하루 → 엑셀 → 오른쪽 칸
   - 매장 **[전체]** 로 받으면 섞여서 A 가 받지 않습니다. 파일 이름 뒤 (27) 같은 번호는 상관없습니다.
   - A 가 바로 확인: 날짜 · 매장이 맞는지, 엑셀 합계와 맞는지, 반품을 몇 장 찾아 지웠는지
4. ③ 처음 보는 상품만 분류 확인 → ④ 미리보기 숫자 확인
5. **입력완료 · 보고자료 업로드** → C 에 저장 → 폰에 올라감 (못 올리면 C 가 1분마다 다시)
   - 중간에 멈출 때는 **임시저장** (계산 · 보내기 없이 그 PC 에만 보관, 다음에 그 날짜를 열면 이어서)
- 같은 날을 다시 올리면 그 칸이 통째로 바뀝니다 (두 번 더해지지 않음). 늦은 취소가 있었으면 그날 엑셀을 다시 받아 올리면 됩니다.
