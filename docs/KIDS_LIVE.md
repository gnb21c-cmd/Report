# 키즈 실시간 — 통합데스크 → 보고 앱 (2026-10-16)

총괄 관리자가 출근하지 않았어도 **폰 한 화면**에서 지금 키즈를 본다 (사장님 2026-10-16).
보고 앱(B) 첫 화면에서 **오늘(마감 전)을 골랐을 때 '오늘 현재 팔린 수량 (업데이트 시간기준)' 칸을 누르면 '키즈 실시간'** 으로 넘어간다. 지난 날(마감된 실적)은 같은 자리가 '입장권 판매 총 수량' 숫자만 — 누를 수 없고 아래 글도 없다 (근무자 오해 막음, 사장님 10/25) (`apps/view/src/screens/KidsLive.tsx`). 위에서 아래로 오늘 입장 → 열쇠 운용 → 입장료 매출 → 네이버 예약 (열쇠를 오늘 입장 바로 밑으로 — 사장님 10/16)

- **오늘 입장**: 총 판매수 = 네이버 이용완료 + 현장(+1타임) · 서비스 키(판매 아님)는 따로
  - 네 칸 (2026-10-27 사장님): **네이버**(오늘 팔린 네이버 입장권 `people.naver`) · **현장입장**(현장에서 판 입장권 `people.walk` — 이벤트 입장은 통합데스크가 이미 뺌) · **재방문성공**(이벤트 시작일 뒤 다시 와서 돈까스를 받은 수 — 오늘 옆 괄호에 누적, 예 **2(43)** · `revisit.today`(`revisit.total`)) · **이벤트**(입장료 없이 이벤트로 들어온 장수 `walk.event`)
  - 밑에 "(수) = 10월 26일 이후 재방문 누적" (이벤트 시작일 `revisit.from`) · 통합데스크가 아직 `revisit` 을 안 보내면(2.10 전 판 · 이벤트 없음) 재방문성공 칸은 "—"
- **입장료 매출**: 받은 때 기준 — 입장권 장수 × 그날 단가(`kidsPrice`, 평일 12,000 · 휴일 14,000) + **초과요금 결제(POS)** = 합계
  - 초과요금은 키즈 POS 로 실제 결제한 '퇴장시간 + ○○분 지연' 상품만 (`kidsOverPaid` — 오늘은 마감 전 숫자, 15분마다) (2026-10-25 사장님)
  - 통합데스크가 보내는 초과요금 금액(결제 · 받을 금액 · 손님별 금액)은 쓰지 않음 — 현장에서는 안 받거나 안내만 하고 돌려보내거나 POS 로 가서 결제할 수 있어, 데스크 [초과요금 결제]만 눌러도 결제로 세어 날마다 '4건 25,000원'이 나왔음 (10월 실제 지연 결제는 10-24 세 건 40,000원뿐)
- **네이버 예약**: 오늘 합 완료 · 미입장 · 잔여 + 시간 칸(예약 있는 칸만, [모든 시간 보기]) · 지금 칸 칠함
- **열쇠 운용**: 사용 n/45 · 빈 열쇠 · 현장 판매 가능 · 45칸 번호 — 통합데스크 V2.0 처럼 **테두리 = 누구 열쇠**(네이버 예약 흰색 · 밝은 화면은 검정 · **현장 판매 파랑** · 서비스 키 점선, 2026-10-25) · **바탕 = 이용 시간**(이용 중 비움 · 반납 시간 10분 안 분홍 · 넘으면 빨강)
  → 번호를 누르면 아래에서 올라오는 창: **손님 이름 · 전화번호 그대로**(전화 걸기 · 번호 복사) · 열쇠 · 상태(초과요금) · 입장 · 반납 · 수량 · 예약번호/POS 번호 · 대리예약 방문자 · 서비스 키 수령인

**열 때 · 아래로 당겼다 놓을 때 · [새로고침] · 앱으로 돌아올 때** 다시 읽음. 맨 위 "통합데스크 14:05:12 기준 · 방금/n분 전".
3분 넘게 새 현황이 없으면 "통합데스크 소식이 n분째 없어요", 오늘 현황이 없으면 "오늘 현황이 아직 없어요 — 마지막 현황 …".

## 개인정보
- 저장소 원칙은 개인정보를 다루지 않는 것이지만, **키즈 실시간만은 사장님 지시(2026-10-16)로 열쇠를 가진 손님의 이름 · 전화번호를 보여 줌** (열쇠 미반납 때 관리자가 전화)
