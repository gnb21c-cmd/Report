# 재방문 간격 — 통합데스크 → 보고 앱 (2026-10-19)

네이버 예약 손님이 **며칠 만에 다시 오는지** 본다 (사장님 2026-10-19). 재방문 이벤트(10/26 ~)로 방문 도전이 시작되거나 성공한 뒤 다음 방문까지 걸린 일수를 이벤트 전과 견줌.
보고 앱(B) 첫 화면 **'네이버판매' 칸을 누르면 나오는 '네이버 판매 수' 세부 화면 맨 위** (`apps/view/src/screens/KidsDetail.tsx RevisitCard`):

- **반반**: 왼쪽 **과거 4/1 ~ 10/25** · 오른쪽 **이벤트 10/26 ~ 지금** (빨간 테두리, 종료일 전이면 "5/31까지 진행") — 재방문까지 걸린 일수 **많은 순 10개**(2026-10-31 사장님 — 7개에서 늘림 · 통합데스크가 `top` 을 10개 보내야 10개, 7개만 보내면 7개 · **처음 화면은 많은 순 5개만, [모두 보기]를 누르면 10위까지** `REVISIT_SHOW` · `revisitShown`)를 빨리 온 순으로 "1일 9명 · … 7일 최다 19명"
  - 기간 글은 **숫자가 나온 날짜** — 통합데스크가 지난 방문 기록을 아직 다 안 읽었으면 읽은 첫날부터 (예: 과거 9/12 ~ 10/23)
- **각 칸 아래 두 줄** (2026-10-23 사장님 — 왼쪽 과거 4월 ~ 10월 · 오른쪽 이벤트 11월 ~ 5월):
  - **월 평균 재방문** = 재방문 수 ÷ (그 기간 일수 ÷ 30.44). 30일이 안 모였으면 부풀리지 않고 "재방문 (26일) 74번"처럼 지금까지 수
  - **재방문자 비율** = 그 기간 재방문 수(통합데스크) ÷ 같은 날짜들의 **네이버 판매수량(보고 앱 — 자동 수집 · 일괄 등록, 오늘은 마감 전 숫자)** (소수 한 자리 %)
    - 통합데스크에는 그 기간 전체 손님 수가 없어 보고 앱 자료로 (2026-10-23 사장님) — 보고 앱 '총인원 대비 신규 비율(신규 ÷ 판매수량)'과 같은 방식
    - 판매수량이 하루라도 빠진 날이 있으면 "—" (부풀린 비율을 보여 주지 않음 — 4/1 ~ 10/22 실제 자료는 205일 모두 있음)
- 예전 맨 위 한 줄 요약(지난 30일 재방문)과 맨 아래 설명(통합데스크 몇 시 기준 · 방문 기록 며칠)은 뺌 (2026-10-23 사장님 — 불필요). 규칙 `packages/core/src/deskRevisit.ts revisitStats`

고른 날짜와 상관없이 통합데스크가 마지막으로 보낸 것(하루 한 번 20:00)을 보여 줌. 날마다의 누계는 안 남김 (사장님: 없어도 됨).

## 흐름
1. 키즈 POS 통합데스크(gnb21c-cmd/astanakiz, 1.50 ~)가 날마다 네이버 이용완료 손님을 그 PC 에만 기록(전화번호를 비밀값과 섞은 해시 — 이름 · 전화 없음)하고,
   데스크가 생기기 전(4/1 ~) 기록은 매일 20:00 보낸 뒤 저절로 네이버 예약현황에서 하루씩 읽음 (처음엔 몇 시간 · POS 를 끄면 다음 날 20:00 이어서 · 다 읽으면 한 번 더 보냄)
2. **매일 20:00 (POS 가 꺼져 있지 않은 때 — 사장님 2026-10-19) 키즈 데스크가 보냄**: 일수 모음(`astanakiz-revisit`, 손님 정보 없음)을 클라우드 `boards/{열쇠}/deskStats/revisit` 에 덮어씀 (설문 보고함 · 키즈 실시간과 같은 보고 열쇠). 통합데스크 쪽 설명 · 글 모양은 astanakiz `docs/REVISIT.md`
3. B 가 화면을 열 때 그 한 문서를 읽어(`apps/view/src/data/firebase.ts deskRevisitNow`) 검사(`packages/core/src/deskRevisit.ts parseDeskRevisit` — 모양이 틀리면 안 보임 · 순위 10개까지 · 이상한 칸은 뺌)한 뒤 그림 (아래 두 줄은 `revisitStats`)

## 세는 법 (통합데스크가 셈)
- 방문 = 그날 네이버 이용완료 (같은 날 여러 건 = 한 번) · 손님 = 전화번호 · 간격 = 같은 손님의 바로 앞 방문 → 다음 방문 일수
- 과거 · 이벤트는 두 방문이 모두 그 기간 안일 때만 (경계를 넘는 재방문은 어느 쪽에도 안 셈)
- 순위 = 사람 수 많은 순, 같으면 짧은 일수 먼저

## 새로 세는 법 · 신규 · 기존 나눠 보기 — 통합데스크가 바꿀 것 (2026-10-31 사장님)
목적: 4/1 부터 유료. **신규**(4/1 이후 처음 온 손님 — 처음부터 유료)와 **기존**(4/1 전부터 교환권으로 무료 이용하다 유료로 바뀐 손님)이
이벤트를 모를 때(과거)와 알게 된 뒤(이벤트 — 다시 무료가 된 느낌) 다시 오기까지 며칠 걸리는지 견줌
- **손님마다 기간별로 한 번만** 셈 (지금처럼 기간 안 모든 간격을 세면 단골이 여러 번 세어짐)
- **과거** = 그 손님이 4/1 이후 처음 온 날이 4/1 ~ 10/25(이벤트 시작 전날)이면, 그날 → 그다음 방문 일수. **다음 방문이 10/26 뒤여도 과거** (매일 다시 셈 · 아직 다음 방문이 없으면 안 셈)
- **이벤트** = 그 손님이 10/26 뒤 처음 온 날(새 손님이든 단골의 N번째 방문이든) → 그다음 방문(N+1) 일수. N+1 → N+2 는 안 셈
- 예) 손님 갑 5/3 · 5/20 · 6/10 · 10/28 · 11/2 → 과거 17일(5/3 → 5/20) · 이벤트 5일(10/28 → 11/2) / 손님 을 10/20 · 11/1 → 과거 12일, 이벤트는 11/1 → 다음 방문
- **신규 · 기존**: 4/1 이후 첫 방문 때 네이버 카드 '완료 n' 이 1 이면 신규, 2 이상이면 기존 (완료 횟수를 모르는 손님은 전체에만) — 지난 방문 기록을 읽을 때 완료 횟수도 남겨야 함
- 과거가 맞으려면 방문 기록이 4/1 부터 있어야 함 (10/31 받은 것은 9/12 ~ 10/31 · 50일 — 통합데스크 운영 설정 → 기타 → [지난 방문 기록 읽기])
- 글 모양: `past` · `event` 안에 지금 칸(`revisits` · `people` · `top` = 전체)에 더해 `groups` (없으면 옛 판으로 보고 전체만 보임 · 한쪽만 와도 됨)
```jsonc
"past": { "from": "2026-04-01", "to": "2026-10-25", "revisits": 512, "people": 301, "top": [ { "days": 7, "count": 82 }, … ],   // 전체 (많은 순 10개)
          "groups": { "new": { "revisits": 300, "people": 180, "top": [ … 많은 순 10개 ] },                                   // 신규
                      "old": { "revisits": 212, "people": 121, "top": [ … ] } } }                                            // 기존
"event": { …, "groups": { "new": { … }, "old": { … } } }
```
- 보고 앱(`packages/core/src/deskRevisit.ts` `REVISIT_KINDS` · `revisitGroup` · `revisitShare`): 두 칸 위에 **[전체 · 신규 · 기존]** 단추 (통합데스크가 `groups` 를 보내야 보임) — 신규 · 기존을 고르면 두 칸 순위 · 월 평균 재방문이 그 무리로, 아래 '재방문자 비율' 자리는 **'전체 재방문 중 n%'** (분모 네이버 판매수량은 무리로 못 나눠서) · 통합데스크가 한 무리를 안 보냈으면 그 칸 "통합데스크 새 판부터 보여요"

## 처음 한 번 (사장님)
1. **Firebase 콘솔 → Firestore Database → 규칙** 에 이 저장소 `firebase/firestore.rules` 전체를 붙여 넣고 [게시] (`deskStats` 규칙이 새로 들어감 — Deploy 는 화면만 올림)
2. 키즈 POS 통합데스크를 1.50 으로 (보고 열쇠는 설문 보고함과 같은 것) → 그날 20:00 에 첫 보냄 + 지난 기록 읽기가 저절로 시작 (몇 시간 · 끄면 다음 날 이어서 · 다 읽으면 한 번 더 보냄). 지금 바로 하려면 운영 설정 → 설문조사 '재방문 간격' [지난 방문 기록 읽기]
