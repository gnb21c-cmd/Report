| 이름 | 어디                                   | 하는 일                                                                                       |
| ---- | -------------------------------------- | --------------------------------------------------------------------------------------------- |

## 2. 왜 C 가 직접 폰에 주지 않고 Firebase 를 거치나

C 는 사무실 공유기 안에 있어, 폰이 밖(LTE · 집)에서 C 로 바로 들어오려면 공유기 포트를 열어야 합니다(보안 위험 · 공유기 설정).
그래서 C 가 **나가는 방향으로만** Google Firebase(무료 사용량 안, 관리할 서버 없음)에 올리고, 폰은 거기서 받습니다.
사무실 안에서는 `http://C이름:8770/b/` 로 C 에서 바로 볼 수도 있습니다 (클라우드 설정 전 시험에도 씀).

```
A(직원 PC) ─ HTTP(사무실 공유기 안, 사무실 비밀번호) ─▶ C ─ HTTPS(올리기 전용 계정) ─▶ Firebase boards/{열쇠}/reports · weather ─▶ B(폰)
```

## 3. 영수증별 매출 상세현황 엑셀 (2026-10-02 실제 파일로 확인)

- 위쪽 `조회일자 : 2026-10-02` (하루치만 받음 — 날짜 칸이 줄마다 없음), 아래 `합계` 줄
- 칸: 포스번호 · 영수증번호 · 구분 · 테이블명 · 최초주문 · 결제시각 · 상품코드 · 바코드 · 상품명 · 수량 · 총매출액 · ERP 매핑코드 · 비고 · 할인액 · 할인구분 · 실매출액 · 가액 · 부가세
- **안 쓰는 칸**: 테이블명 · 결제시각 · 상품코드 · 바코드 · ERP 매핑코드 · 비고 (할인구분 · 가액 · 부가세도). 시각은 **최초주문**
- **팀** = 같은 포스번호 + 같은 영수증번호 (포스 01 · 02 는 번호가 따로 매겨짐 → 01-0001 과 02-0001 은 다른 팀)
  - 팀 인원 = 그 팀의 음료 잔 수 (예: 01-0001 자몽에이드 1 · 아이스아메리카노 1 · 돈까스 · 리조또 · 치즈볼 → 2명)
- **구분 = 반품** 은 새 영수증번호로 찍힘 (10/2: 반품 6장 15줄). 반품 영수증의 상품이 모두 든 **앞선 매출 영수증**(같은 포스 먼저, 가장 가까운 시각)을 찾아 그 줄들을 지움
  - 10/2 실제: 6장 모두 영수증 통째로 짝이 맞음 (예: 01-0200 반품 = 01-0195 비프스테이크 · 리조또 · 아메리카노 2). 100% 서비스 할인(0원) 영수증 반품도 짝을 찾음
  - 그런 영수증이 없으면 상품마다 앞선 매출 줄에서 빼고(일부 반품), 그래도 없으면 음수 줄로 남기고 A 화면에 알림
  - 지운 뒤 실매출 합 = 엑셀 합계 줄 (10/2: 6,628,100원 일치)
- 대분류 칸이 없어 **상품 분류표**(C 보관, 상품명 → 바리스타 · 베이커리 · 키친 · 기타)로 나눔
  - 처음 보는 상품은 이름으로 짐작해 A 화면에서 한 번 확인 → 분류표에 저장. 상품별(일자별) 엑셀을 '지난 자료'로 넣으면 OK포스 대분류로 채워짐
- A 가 확인하는 것: 조회일자 = 입력 날짜(하루), 매장이 맞는지(입장권이 대부분이면 키즈, 음료·빵이면 카페, 섞였으면 [전체]로 받은 것), 같은 파일을 두 칸에 올렸는지, 합계 일치

## 4. A 입력 화면 (apps/entry)

- 직원 PC 바탕화면 아이콘 → Edge(없으면 Chrome) 앱 창 **전체 화면**으로 C 의 화면을 엶 (설치할 프로그램 없음, C 를 고치면 모두 같이 바뀜)
- 맨 위: **"yy년 mm월 dd일 기준 -1일 전의 일자 (영업마감 현재) 기준 영업 데이터를 입력하세요"** + 입력할 영업일(기본 어제, ◀ ▶ · 달력) + 그날 기상청 날씨 + C 에 이미 올라간 조각(누가 언제)
- ① 네이버 예약 표: 열 10:00 ~ 19:30 (30분, 20칸) · 줄 **판매입장권 수 / 신규방문자 수**(마감 현재 방문 완료 횟수 1인 사람). 엑셀처럼 칸 이동 · 붙여넣기
- ② 영수증별 엑셀 두 칸: **카페아스타나 · 아스타나키즈** 따로 (끌어다 놓기 · 파일 선택, 받는 방법 안내)
- ③ 새 상품 분류 확인 ④ 보고 미리보기 (지금 입력 + C 에 있는 것을 합친 폰 숫자)
- **임시저장**: 계산 없이 넣은 값과 엑셀 파일을 그 PC(브라우저 저장소)에만 보관. 그 날짜를 다시 열면 이어서
- **입력완료 · 보고자료 업로드**: A 에서 계산 → 확인 창 → C 로. 보낸 조각만 바뀌고 나머지는 C 에 있던 것 그대로 (각자 맡은 칸만 넣어도 됨)
- 입력자 이름은 PC 마다 한 번 (보고 앱 설정의 '최근 입력 현황'에 남음). C 에 사무실 비밀번호를 정했으면 한 번 넣음
- 지난 자료 한꺼번에 넣기: 상품별(일자별) 엑셀(기간) → 하루 합계 조각 (시간대 없음, 영수증별로 올린 날은 안 바꿈)

## 5. C 사무실 PC (apps/office)

- PC 를 켜면 로그인 없이 저절로 시작 (작업 스케줄러, 꺼지면 1분 뒤 다시), 전원 연결 상태 절전 끔
- 방화벽: 사무실 공유기 안에서만 TCP 8770 (A · B 화면) · UDP 8771 (직원 PC 가 C 를 찾음). 사설 주소가 아니면 거부
- 보관함 `C:\ProgramData\PosReport\office.db` — 조각(parts) · 합친 보고(reports) · 정리한 영수증 줄(lines, 다시 계산용) · 분류표 · 날씨 · 못 올린 것(outbox)
- 클라우드 설정 전에는 **시험 모드** (C 에만 쌓고 `/b/` 로 봄). 설정 뒤 `republish` 로 한꺼번에 올림
- 기상청: 1시간마다 관측 빈 날 + 오늘 예보. 관측이 예보를 바꾸고, 예보는 관측을 못 바꿈

## 7. 계산 규칙 (`packages/core/src/rules.ts` · `part.ts` · `metrics.ts`)

- 바리스타 · 베이커리 · 키친 = 카페아스타나 분류별 실매출 (반품 지운 뒤)
- 기타 = 카페아스타나 기타 + 아스타나키즈 입장권 외 매출 (추가 인원 · 간식 등)
- 키즈입장료 = (네이버 입장권 + 현장 입장권) × 단가. 단가: 평일 12,000원, 평일 외(토 · 일 · 공휴일 · 대체공휴일) 14,000원
  - 네이버 입장권 = **A 에 넣은 시간대별 판매입장권 합**. 아직 안 넣은 날은 키즈 POS 로 추정 (0원 입장 발행 − 현장, 10/1: 20 − 4 = 16) — 지난 자료도 이것으로
  - 현장 입장권 = 키즈 POS 에서 돈을 받은 입장권 ('[평일]/[휴일] 1시간 50분 입장권')
  - 이벤트 무료입장 = 0원 쿠폰 입장 팀 수 ('[평일] 한가위 무제한 쿠폰'). 입장료 · 잔 수에 안 들어감
- 상품권 결제 ('[종이쿠폰]만원권' · '[아키 2만원] 교환권' 음수 줄) = 미리 산 현금성 상품권으로 낸 결제 수단 → 매출에서 빼지 않고 잔으로도 세지 않음
- 총 매출 = 다섯 상자의 합 (네이버 입장권 매출이 들어가므로 POS 실매출 합보다 큼)
- 카페아스타나 방문인원 = 카페 음료 · 맥주 잔 수 × 0.96 (옵션 · 0원 · 아이스크림 · 드립백 빼고, '맥주2+감자튀김' 은 2잔). 1인 평균소비 = 총 매출 ÷ 방문인원
- 시간대: 10시 ~ 22시 한 시간씩 12칸, 최초주문 시각 (10시 전은 10시 칸, 22시 넘으면 21시 칸)
- 작년 자료가 기간의 80% 미만이면 비교(%)를 하지 않고 "작년 자료 n일치뿐" 으로 표시
- 기간 스티커 (`weather.ts` SEASONS, **기본값 — 사장님 확인 필요**): 성수기 = 여름방학 7/20~8/20 · 겨울방학 12/24~2/28 · 5월, 비수기 = 3/2~3/31 · 6/20~7/10 · 11월, 나머지 평상시

| 서버       | 따로 운영하지 않음. 사무실 PC C 가 서버 역할, 폰으로는 Firebase(구글 운영)를 우편함으로 → [SETUP.md](SETUP.md) |
| 입력       | 사무실 직원이 A 에서 각자 맡은 칸만. 매장 근무자 · POS PC 는 할 일 없음                                        |
| 자료       | 영수증별 매출 상세현황 엑셀 (매장별 · 하루). 지난 자료는 상품별(일자별) 엑셀                                   |
| 계산       | A 에서 매장 하루치(분류 · 시간대 · 팀 · 잔 · 상품 · 키즈 입장)를 계산, B 가 여러 날 비교 · 분석               |
| 보는 기준  | 받은 자료 중 가장 늦은 마감일(보통 어제) — 앱 위 달력에서 지난 날도 봄                                         |

## 9. 만든 것 (브랜치 `feature/report-mvp`)

| 경로            | 내용                                                                                                              |

| `packages/core` | 영수증 엑셀 읽기 · 반품 지우기(`receipt.ts`), 매장 하루치 계산(`part.ts`), 지난 자료(`daily.ts`), 대시보드 · 누계(`metrics.ts`), 시간대 분석 · 예측 · 하위 5개(`hourly.ts`) + 시험 |
