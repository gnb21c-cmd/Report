# 이벤트 무료입장 — 통합데스크 → 보고 앱 (2026-10-21)

보고 앱(B) 키즈 칸의 **'이벤트 무료입장'** (예: 한가위 무제한 쿠폰으로 들어온 손님 수).

- 예전: 키즈 POS 에 0원으로 만든 이벤트 상품(예 '[평일] 한가위 무제한 쿠폰', 분류 '이벤트무료' — `classify.ts`)을 찍은 수량
- 이제(통합데스크 2.1 ~, 사장님 2026-10-21): 이벤트 손님은 POS 를 거치지 않고 **통합데스크 현장입장 창의 [한가위 이벤트 입장]** 으로 바로 들어감 → POS 에 안 잡힘
  → **통합데스크가 그날 이벤트 입장 수를 보냄**

## 흐름
1. 키즈 POS 통합데스크: 현장입장 창 아래 왼쪽 [이벤트 입장] (이름은 통합데스크 운영 설정 → 기타 '현장 이벤트 이름', 예 한가위 → [한가위 이벤트 입장]) — 열쇠 · 입장권 · 인원은 현장 손님과 같고 결제가 없어 통합데스크 총 판매수에는 안 셈
2. **매일 20:00** (설문 누적을 보내는 때와 같이 · 설문을 안 하는 기간에도 이것만 · 하루 한 번, 20:00 뒤 숫자가 바뀌면 다시 · 실패하면 10분 뒤) 클라우드 `boards/{열쇠}/deskStats/event-{날짜}` 에 덮어씀 (설문 보고함 · 키즈 실시간과 같은 보고 열쇠). 이벤트 손님이 없는 날도 0
   ```json
   { "type": "astanakiz-event", "v": 1, "day": "2026-10-21", "sentAt": "2026-10-21 20:00", "count": 3, "names": [{ "name": "한가위", "n": 3 }] }
   ```
   손님 정보 없음 (수 · 이벤트 이름만)
3. B 가 자료를 받을 때 `deskStats` 의 `event-날짜` 문서를 모두 읽고(`apps/view/src/data/firebase.ts deskEvents`), 열려 있는 동안 5분마다 오늘 것 하나만 다시(`deskEventDay`) — 검사 `packages/core/src/deskEvent.ts parseDeskEvent`
4. 그날 키즈 **이벤트 무료입장 = max(POS 0원 상품, 통합데스크)** (`withDeskEvents`) — 옮겨 가는 동안 같은 손님을 POS 에도 찍었을 수 있어 더하지 않음. 입장료 · 잔 수 계산에는 예전처럼 안 들어감 (장 수만)
   - 오늘(마감 전)은 20:00 에 통합데스크가 보낸 뒤부터 · 그 전에는 POS 숫자
   - 시간대별(이벤트 무료입장 시간 칸)은 POS 것 그대로 (통합데스크는 하루 합만 보냄)
